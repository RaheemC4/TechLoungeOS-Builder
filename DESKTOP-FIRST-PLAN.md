# Desktop-first provisioning: approved 31 October 2026

This is the approved implementation and acceptance plan. Draft source now implements the queue and progress surface, but live interaction, SYSTEM execution and fresh-install timing remain acceptance gates. The user chose a fast first desktop, with selected apps and Office finishing quietly afterwards, visible progress and retry support. Earlier Ghost and the accepted standard export cover the former timing.

The user startup helper must wait for a stable visible Explorer desktop. It must never hold Windows Setup waiting for application installers or automatically elevate an ordinary user. Keep fast account/automatic-sign-in setup and initial personalisation separate from long installations. Show one non-modal progress surface, not individual installer windows. Closing it must not interrupt installation. Keep successful receipts and make failed steps retryable without reinstalling successful apps. Do not display invented time percentages.

Windows Setup will register one immutable, protected SYSTEM action, without an automatic boot trigger. The desktop helper requests that fixed action after shell readiness. Keep payload signatures/hashes, ACL protection, path/reparse checks and an exclusive installer lock. Registration must not download or install software. Defer Builder-owned runtimes, Edge, Store/Xbox, HWiNFO, Office and optional-feature servicing; preserve original source hooks and disclose that their own work or Windows hardware initialisation can still cause delay. Provide an elevated Windows-Setup account callback for registration if the source's OEM channel skips SetupComplete; do not add a normal-user elevation fallback.

Keep the guide's Office folder/setup.exe/configuration in the ISO's correct sources/$OEM$/$$/Setup/Scripts location. After desktop readiness, copy pinned installer inputs into a newly protected SYSTEM-owned cache. Deny concurrent source writers/deletion, check exact input hashes, flush and independently hash the copied bytes before any installer can run. This avoids trusting an older custom ISO folder ACL or moving a directory with pre-existing user handles into a privileged execution path. Keep large copies and hashing out of Windows Setup; budget the temporary target-disk space. Execute the same setup.exe /configure Configuration.xml command from the verified Office cache. A source conflict or unsafe cache path must fail clearly. Keep the supplied Standalone bytes unchanged and do not change Office licensing behaviour as part of this timing work.

Required machine installers must finish before dependent user apps. Apply independent wallpaper, dark/taskbar/input preferences promptly so a long Office install does not delay desktop personalisation. Do not kill Explorer to apply these settings. Retain all app selections, including the required Discord/OpenAsar path and desktop icons. Boot Optimizer and Standalone must remain after successful app and Office receipts. Driver installers must not race application installation.

Progress must distinguish waiting, running, failed/retryable, restart-needed and complete, survive an ordinary reboot, and be readable without granting the user write access to SYSTEM actions. A stalled installer must not prevent desktop use or produce a success receipt. Bound waiting for shell readiness and check elapsed deadlines between operations; do not apply a scheduler hard timeout that can terminate active Windows servicing. Preserve installer PID/start-time identity so retry cannot start a duplicate while a previous process is still running. Never force a restart or terminate Windows servicing to meet a timer.

Incremental checks: stable/unstable/absent desktop gate; task registration versus execution; protected input/action rejection; no pre-desktop installer execution; per-step ordering, failure and resume; same-user duplicate startup; desktop progress accessibility and reduced motion; ordinary-user retry; full fresh standard and Ghost installs with measured first-desktop and install-completion times. Gate, input-copy, harmless real-child failure/retry/interruption, off-screen font/render/close and driver app-order fixtures pass. The731-check run predates the final restart-notice/export-phase refinements. Preparing a VM interface test was rejected by automatic approval review; that command did not run. Do not count fixtures or off-screen rendering as the remaining live acceptance.
