# WinPE setup and original tools

The current Builder enables the redesigned setup environment by default. It replaces the recognised Ghost Spectre LaunchBar with a native toolbar, animated background and account wizard. Original tool executables and unrelated startup entries are preserved byte for byte. Third-party tool windows keep their own interfaces.

Draft 0.1.21 reads the WIM header and metadata to find its marked x64 Windows PE boot image; it no longer assumes index 2. It supports the recognised Ghost LaunchBar entry and adds a separate standard-image path only when the source has no winpeshl.ini, a plain wpeinit startnet.cmd and the matching standard setup registry state. Unknown startup scripts, ambiguous metadata, unsupported encodings, missing prerequisites and existing Builder integrations stop the private build with an explanation. Deselecting animated setup keeps the source boot image unchanged. Real standard-image boot and installation acceptance are pending; this draft is unreleased.

The new shell stays in the foreground launch position so WinPE does not reboot when initialization ends. For Ghost, the copied boot image gains its native executable, an exact startup-file backup, two account templates, a media identity and three licensed Manrope font files. The Builder hashes all inherited WinPE files before and after staging. Only `winpeshl.ini` may change; added files must match the explicit allowlist. The original ISO is never opened for writing.

The wizard accepts a username, optional PC name, optional password, automatic sign-in preference and optional request to open Windows Hello settings after installation. A blank PC name derives from the username. Password confirmation appears only after password entry and disappears after clearing and leaving that field. Region and keyboard choices come from the Builder. Credentials are rendered on the WinPE RAM drive for installation handoff. Choosing a Hello request does not enrol a PIN inside WinPE or guarantee passkey compatibility.

The interface has privately loaded Manrope typography, rounded focus/hover feedback, labelled checkbox click areas and reduced-motion/high-contrast fallbacks. Text input remains immediate. The shell uses native Win32/GDI; it needs no browser or managed runtime. The installed Windows account helper separately requires retained .NET Framework 4.

## Current native evidence

The exact ISO1250/16 GB virtual USB1255 booted with Microsoft Secure Boot and TPM2 in fresh1263. Native captures showed five distinct ambient-animation frames without input. The replacement toolbar found 21 inherited tool shortcuts and opened the original CPU-Z. Actual typing checks passed Ctrl+Backspace, username/password copy and paste, conditional password confirmation and checkbox-label clicks.

That same media completed a fresh Windows installation with a nonempty disposable password, automatic sign-in and a blank optional PC name. It reached the desktop without further account, network, privacy, region or keyboard questions. Internal recovery and an ordinary restart both returned automatically to the same account. All 27 recorded installation gates passed again after each return. See [TEST-RESULTS.md](TEST-RESULTS.md) for reports and observation limits.

A separate legacy BIOS/Nehalem-model VM with no TPM booted the exact virtual USB, displayed the toolbar and account form at 1024x768, opened its original tools and shut down normally. This was a WinPE boot test, not a complete legacy installation or proof that Windows can run on processors missing required kernel instructions.

Physical USB/PC use, GPU frame presentation, physical multi-monitor layouts, all third-party tool operations, full accessibility semantics and Windows Hello/passkey enrolment remain unverified. The standard WinPE power-confirmation dialog retains its native system styling. No universal compatibility claim is made.

Draft standard-image tools: standard-image tool lists include available Windows command prompt, Registry Editor, Notepad and disk console entries alongside the original shortcuts, without duplicating an equivalent Registry Editor entry. Files uses the unmodified, pinned Explorer++ 1.4.0 x64 fallback, with its matching source archive and GPL licence alongside it. Common Controls 6 is checked in the original WinSxS assembly and manifest; no Windows DLL is copied from the build host. Existing Ghost shortcuts and tool binaries take precedence. This draft still needs actual standard-image launch checks.

The standard PE-only candidate has now booted at1920x1080 in a4GB VM, and Windows PE reports UEFI firmware with Secure Boot enabled. Files browsed the bundled Explorer++ folder. Later tool-list and regular-font corrections passed RAM-only launches in that real environment; the final image with those corrections still needs rebuilding and full-install acceptance. The bundled Manrope faces are shared only inside the standard WinPE RAM session for regular tool-window captions/menus/messages, with nonclient metrics restored at cleanup; custom-image preferences bypass this setup. Existing file-manager preferences are preserved, and only a new fallback settings key receives compact first-run defaults.
