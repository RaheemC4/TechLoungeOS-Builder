# Builder engineering requirements

Read `COMPATIBILITY.md` and `TEST-RESULTS.md` before changing the builder.

Read and write source text with explicit UTF-8. Legacy code-page round trips previously corrupted visible WPF punctuation. Run the compiled-interface copy checks after editing captions. Preserve the byte-exact Boot Optimizer and supplied Standalone files; their Git attributes disable newline conversion.

The user authorised bundled Edge Stable as the default browser on 26 October. Use its verified offline enterprise MSI and supported DISM default associations for new users. Preserve non-browser associations and existing user choices. Edge and the selected Store/Xbox restoration are explicit exceptions to source removals; do not restore other stripped features or disable Discord security prompts. Do not treat the targeted VM recovery tests as a fresh ISO installation pass.

For each material change, identify which users or environments may fail, validate prerequisites early, preserve original media and unrelated mounts, and add regression coverage for supported failure cases. Do not claim universal support or installation readiness from compilation, fixture tests or interface renders.

Keep first-login work safe for standard users: isolate steps, retain successes, report failures, avoid automatic privilege escalation and keep retries idempotent. The user authorised the reviewed Recommended subset for ISO installation on 25 October: exclude Windows Update pauses, all Defender changes and GPU-specific changes. Use the Builder's explicit positive list, not bulk preset calls or future unreviewed upstream additions. Keep the original Tweaks release and its manual presets unchanged.

Update the support matrix and actual test record when behaviour changes. Preserve the existing TechLoungeTweaks implementation. Do not push, publish, merge or create a remote PR without the user's approval.

The user subsequently authorised automatic NVIDIA profile application and current compatible driver installation on NVIDIA-equipped target machines only. Keep this as a separate hardware-gated post-install option; do not broaden the ten-tweak Recommended list. Never use the build host's GPU to select a target driver, guess unknown GPU families, modify AMD/Intel adapters or force restarts. Keep large driver payloads out of the ISO and enforce the default conservative 16 GB media budget. Driver setup may create its own finite-purpose SYSTEM task at first sign-in/startup; unregister it after completion and report failures without bypassing security or Windows Update policy.

The user also authorised AMD/Intel display-driver queues on 25 October, conditional on installed target graphics hardware. This supersedes the prohibition on updating AMD/Intel adapters above, but not on applying NVIDIA profiles to them. Queue only vendors positively detected as display devices; CPU/chipset branding is not GPU evidence. Handle hybrid systems, retain successes independently and serialize graphics installers. Currently AMD/Intel use clearly labelled hardware-matched Windows Update packages; do not claim they are necessarily the newest vendor reference releases. The user explicitly selected hardware-matched Windows Update drivers for AMD/Intel on 25 October 2026. Preserve that selection; do not substitute vendor reference packages or auto-detect utilities.

Alongside automated checks, use the packaged app as an ordinary user. Exercise choosing, changing and removing options, cancelling dialogs, navigating back, and reading errors. Fix reproducible friction and record actual clicks separately from fixtures and installation proof. Do not certify usability from renders alone.
